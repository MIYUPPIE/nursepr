# NursePrep

Exam prep for Nigerian nursing licensure candidates (NMCN): untimed practice
with instant feedback, timed mock exams in the real NMCN format, a daily quiz
delivered over WhatsApp, and an AI tutor-with a readiness score and
weak-area breakdown to show where you actually stand.

## Running locally

* `mix setup`-installs deps, creates/migrates the database, builds assets
* `mix phx.server` (or `iex -S mix phx.server`)-starts the app at
  [`localhost:4000`](http://localhost:4000)

Login is WhatsApp-OTP based. Without real Evolution API credentials
configured (see below), the dev login page prints the OTP directly on
screen instead of sending it over WhatsApp.

## External services

Configured via environment variables, read at runtime (see
`config/runtime.exs`). All are optional for local dev-the app boots
and the test suite runs with none of them set.

| Service | Env vars | Powers |
|---|---|---|
| [Evolution API](https://doc.evolution-api.com/) (self-hosted WhatsApp gateway) | `EVOLUTION_API_BASE_URL`, `EVOLUTION_API_INSTANCE`, `EVOLUTION_API_KEY`, `EVOLUTION_WEBHOOK_TOKEN` | WhatsApp login OTPs, the daily quiz drop, and the WhatsApp quiz/tutor flow |
| [Telegram Bot API](https://core.telegram.org/bots/api) (fallback channel) | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` | The same login/daily-quiz/tutor flows, over Telegram-official API, no self-hosted gateway needed. Used standalone by any student who links it, and as the automatic fallback for proactive sends when WhatsApp is down |
| Paystack | `PAYSTACK_SECRET_KEY`, `PAYSTACK_PUBLIC_KEY` | Subscription payments |
| xAI / Grok | `X_API_KEY`, `XAI_MODEL` | AI tutor and AI-assisted question cleanup |

## Question bank pipeline

Practice/exam sessions only ever draw from `status: "published"` questions.
Nothing publishes automatically:

1. **Ingest**-`/admin/ingestion` parses `priv/source_data/nursing_questions.docx`
   into `draft`/`flagged_manual_review` question rows, each with a pending
   review.
2. **Review**-`/admin/review-queue` is where a human accepts, edits, or
   rejects each one (optionally starting from an AI cleanup suggestion).
3. **Publish**-a question is only answerable by students once every one
   of its reviews is approved.

## Tests

* `mix precommit`-the full gate: compile with warnings-as-errors, format
  check, `mix test`
* `mix test test/evals`-periodic (paid, LLM-backed) quality evals; not part
  of the commit gate

## Production deployment

Runs as a Docker Compose stack on a single VPS: the Phoenix release (built
from the `Dockerfile` generated by `mix phx.gen.release --docker`), its own
Postgres, the Evolution API WhatsApp gateway stack (`evolution-api` +
its own isolated Postgres + Redis), and Caddy in front for automatic
Let's Encrypt HTTPS. All five services are defined in
`docker-compose.prod.yml` and share one Docker network, addressing each
other by service name (`app`, `app-db`, `evolution-api`, `evolution-postgres`,
`evolution-redis`, `caddy`).

Secrets live in `/opt/nurseprep/.env.prod` on the server only-generated
once at initial setup (`SECRET_KEY_BASE`, DB passwords, the Evolution
`AUTHENTICATION_API_KEY`/webhook token) plus whatever real third-party
keys (Paystack, X.AI, SMTP) are available at the time. Never committed;
`.gitignore` excludes `.env*` except `.env.example`.

Redeploy after pushing changes:

```
bin/deploy.sh
```

This rsyncs the working tree to the server, rebuilds the `app` image,
runs `bin/migrate` inside a throwaway container, restarts the stack, and
smoke-tests `https://nurseprep.com.ng/`.

Backups: `bin/nurseprep_backup.sh` runs daily via cron on the server
(`pg_dump` of both the app DB and Evolution's DB, gzipped, 7-day local
retention in `/opt/nurseprep/backups/`). Off-server/offsite copies are
not yet wired up-add an S3/B2 sync there before this holds anything
you can't afford to lose.

Pairing WhatsApp: the Evolution instance's QR code is only valid for
~30s at a time. Re-fetch it with:

```
ssh nurseprep-prod
cd /opt/nurseprep
source <(grep -E '^EVOLUTION_API_KEY=' .env.prod | sed 's/EVOLUTION_API_KEY/AUTHENTICATION_API_KEY/')
curl -s http://localhost:8080/instance/connect/nurseprep -H "apikey: $AUTHENTICATION_API_KEY" \
  | python3 -c "import json,base64,sys; d=json.load(sys.stdin); open('/root/qr.png','wb').write(base64.b64decode(d['base64'].split(',',1)[1]))"
```

then `scp nurseprep-prod:/root/qr.png .` and scan it from WhatsApp ->
Settings -> Linked Devices -> Link a device.

## Telegram Bot API (production)

Unlike Evolution API, Telegram's Bot API is a hosted service-no self-hosted
gateway, no dedicated Postgres/Redis, nothing to add to
`docker-compose.prod.yml`. Setup is a one-time bot registration plus three
env vars in `.env.prod`.

1. Create the bot: message [@BotFather](https://t.me/BotFather) on Telegram,
   `/newbot`, choose a name/username. It replies with a token shaped like
   `123456789:AAExampleTokenAbcDefGhiJklMnoPqrStuVwx`-that's
   `TELEGRAM_BOT_TOKEN`. The username you chose (without the leading `@`)
   is `TELEGRAM_BOT_USERNAME`-powers the "Open the NursePrep Telegram bot"
   deep link on the settings page (`Messaging.telegram_bot_url/0`); confirm
   it any time with `curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getMe"`.
2. Generate a webhook secret (must be 1-256 chars from `A-Z a-z 0-9 _ -`;
   URL-safe base64 fits exactly):
   ```
   elixir -e 'IO.puts(:crypto.strong_rand_bytes(32) |> Base.url_encode64(padding: false))'
   ```
   That's `TELEGRAM_WEBHOOK_SECRET`.
3. Add all three to `/opt/nurseprep/.env.prod` (same gitignored secrets file
   as `EVOLUTION_API_KEY`), then `bin/deploy.sh` as usual.
4. Register the webhook once, after deploy:
   ```
   ssh nurseprep-prod
   source <(grep -E '^TELEGRAM_(BOT_TOKEN|WEBHOOK_SECRET)=' /opt/nurseprep/.env.prod)
   curl -s -X POST "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/setWebhook" \
     -H "Content-Type: application/json" \
     -d "{\"url\": \"https://nurseprep.com.ng/webhooks/telegram\", \"secret_token\": \"$TELEGRAM_WEBHOOK_SECRET\"}"
   ```
   Verify with `curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getWebhookInfo"`-the
   response should show the registered URL and no `last_error_message`.

A student links Telegram by starting a chat with the bot and replying with
their account's phone number or email when asked
(`Whatsapp.Session.route_telegram_confirmation/2`)-Telegram can't push a
message to a chat id that's never messaged the bot first, so this only ever
works for an already-registered account, never as a cold-start signup
channel. Once linked, `Accounts.request_otp/1` automatically routes login
codes there whenever `Whatsapp.ConnectionAlert.connected?/0` says WhatsApp
is down, and `DailyQuizDropWorker` does the same for the daily quiz drop.
